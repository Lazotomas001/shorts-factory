# Shorts Factory: free, automated, faceless YouTube Shorts

**[Privacy Policy](PRIVACY.html) · [Terms of Service](TERMS.html) · Uses YouTube API Services ([YouTube Terms of Service](https://www.youtube.com/t/terms), [Google Privacy Policy](https://policies.google.com/privacy))**

Shorts Factory Uploader is a private, internal tool that Tomas Lazo uses to create original animated Shorts and upload them to his own YouTube channels (e.g. *Bubbo & Friends*).

It makes **original** vertical Shorts for several channels every day and runs free on GitHub Actions.

| Channel | What it makes | Status |
|---|---|---|
| `kids` | Original cartoon characters (Bubbo, Pip, Mimi, Tuko, Zuzu) teaching **counting**, **colors** and **guess-the-shadow**, with narration, sound effects and a backing track | on |
| `holiday` | **Christmas sing-alongs**: public-domain carols (Jingle Bells, Deck the Halls, We Wish You a Merry Christmas, Silent Night) arranged from scratch, with bouncing-ball karaoke lyrics over an animated snowy scene. Runs only Nov 1 – Dec 26 | on |
| `quiz` | 3-question trivia Shorts with timers and reveals (a well-performing faceless format) | off until you enable it |

Everything is generated by code: drawings, animation, music (a built-in synthesizer) and voice (free neural TTS). There are no stock clips, no
copied videos and no licensed music, so you have no copyright exposure and no costs.

## Two rules that shape this whole setup (read these first)

1. **API uploads are locked to private until Google audits your project.** YouTube locks every video uploaded through an
   *unverified* API project as private, and you can't appeal it. The audit is free (form linked below) but takes a while.
   **Until it passes, keep `upload_mode: manual`.** Each day's videos arrive as a download from GitHub with a
   ready-to-paste `UPLOAD_SHEET.md`. Use YouTube Studio's bulk upload and scheduler. That takes about 10 minutes a week.
2. **YouTube won't monetize "inauthentic" (mass-produced, repetitive) content.** It judges the whole channel, not single videos.
   This project is built to stay on the right side of that:
   * Every video randomizes character, format, objects, scene, music key/tempo/instrument, voice and wording.
   * `data/history.json` prevents repeating topics.
   * Kids videos have real teaching value (counting, colors, vocabulary).
   * The manual review step is the human, editorial part YouTube looks for. **Keep watching what goes out**, especially for kids.
   * Moderate cadence by default (2/day per channel). Don't crank it to 20.

Also:
* **Made for Kids**: the kids and holiday channels are set `made_for_kids: true`. COPPA requires this when the audience is
  children. It disables comments and personalized ads, so revenue per view is lower. That's normal for kids content.
* **Synthetic media**: cartoons aren't "realistic" altered content, so the disclosure is set to *No*. If you ever add realistic AI people or voices that imitate real people, set it to *Yes*.

## Setup (about 30 minutes, one time)

### 1. Create the channels
In YouTube, create one **Brand Account channel** per niche (Settings → Add or manage channels → Create a channel).
They can all live under one Google login.

### 2. Put the code on GitHub
Create a new repo (public = unlimited free minutes), upload this folder, then open **Actions → Daily Shorts → Run workflow**
once to test. When it finishes, the videos are under the run's **Artifacts**.

That's already a working pipeline in manual mode.

### 3. (Recommended) Trend research: free API key
Google Cloud Console → new project → enable **YouTube Data API v3** → Credentials → **API key**.
Add it as repo secret `YT_API_KEY`. The weekly *trend report* workflow then writes `reports/trends-<channel>-<date>.md`:
the fastest-growing Shorts in each niche (views/day), common title words and tags. Use it to choose which formats to
make more of (e.g. change `per_day`, add objects/songs, tweak titles). The code makes *similar types* of content to what's
performing, never copies of it.

### 4. (When ready) Fully automatic uploads
1. Same Cloud project → OAuth consent screen (External, add yourself as test user, then **Publish app** so tokens don't
   expire after 7 days) → Credentials → **OAuth client ID → Desktop app** → download as `client_secret.json`.
2. On your computer: `pip install -r requirements.txt` then for each channel
   `python run.py auth --channel kids` (pick that channel's Brand Account in the browser). It prints a refresh token.
3. Repo secrets: `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN_KIDS`, `YT_REFRESH_TOKEN_HOLIDAY`, `YT_REFRESH_TOKEN_QUIZ`.
4. Apply for the audit: https://support.google.com/youtube/contact/yt_api_form. Describe it honestly: "internal tool
   that uploads my own original videos to my own channels".
5. After approval, set `upload_mode: api` in `channels.yaml`. Videos then upload as scheduled posts at your `publish_hours_utc`.

## Everyday commands

```bash
pip install -r requirements.txt        # plus ffmpeg (and espeak-ng as a fallback voice)
python run.py make --channel kids --count 3
python run.py make --channel kids --format counting      # counting | colors | shadow
python run.py make --channel holiday --format silent_night
python run.py daily                                       # what GitHub runs every morning
python run.py trends --channel holiday                    # needs YT_API_KEY
python run.py grow-quiz --n 30                            # needs LLM_* env vars; you approve each question
```

Output goes to `outbox/<date>/<channel>/` with `UPLOAD_SHEET.md` and `manifest.json`.

## Growing it

* **New channel**: copy `channels/quiz.py` as a template, expose `make(out_dir, rng, ledger, channel)` returning
  `{file, title, description, tags, category_id}`, then add an entry to `channels.yaml`.
* **More carols**: add to `channels/carols.py` (only songs whose melody and lyrics were published before 1929).
* **More kids objects/characters**: `channels/cartoon_art.py`.
* **More quiz questions**: `data/quiz_bank.json` (hand-checked), or AI-suggested ones in `data/quiz_extra.json` after you set `"approved": true`.
